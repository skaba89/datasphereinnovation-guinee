# V220 — Préparation systemd PROD (staging inerte)

Six unités dédiées, dans deploy/systemd/staged-prod, distinctes des unités REC. Horaires proposés UTC : backup 01:15, export 02:05, audit 03:00. Toutes les unités service exécutent uniquement /usr/bin/false ; aucun accès Docker, B2, clé ou base. Les timers ne disposent volontairement pas de section Install et Persistent=false. Ne pas copier dans /etc/systemd/system, démarrer ou activer. L'absence de section Install ne bloque pas un démarrage manuel ; le verrou ExecStart est la protection effective de ce lot.

Les tests vérifient la structure exacte, l'absence de commande métier et les horaires. La qualification V219 sur le VPS a prouvé 35 tests et un aller-retour B2 avec preuve persistante sur données synthétiques. Ce lot ne prétend pas automatiser une sauvegarde réelle. Avant un service opérationnel : séparer formellement les objets synthétiques (dont dsig-prod-20261126T100822Z.dsigbak), identifier et attester le volume PROD, définir la clé durable, le verrou commun backup/export/audit, la fraîcheur et la preuve du cycle, qualifier les échecs et alertes, vérifier le budget mémoire et les chevauchements REC. Aucune activation, aucun changement VPS ni production_authorized.
