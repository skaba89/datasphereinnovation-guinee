# V232 — Optimisation du registre B2

Le rapport du 26/11/2026 mesure 150 lectures logiques, 6 écritures et 834,06 secondes pour la campagne complète. Le nouveau lecteur groupe les dix emplacements dans un inventaire de versions frais, télécharge uniquement les preuves présentes et refait l'inventaire après téléchargement. Il refuse version cachée, doublon, objet inconnu, changement de version et preuve trop grande. Pas de cache entre appels; signatures et comparaison canonique restent obligatoires. Avant publication, tous les emplacements sont comparés; après publication, l'inventaire complet est comparé à l'état attendu. Les anciens adaptateurs de test sans méthode groupée restent compatibles. Le lanceur de qualification doit utiliser directement B2QualificationAdapter ou transmettre read_retry_records dans son wrapper de mesures. Les compteurs doivent distinguer appels groupés et commandes CLI réelles. Aucun gain de temps réel n'est affirmé avant nouvelle mesure VPS. Un seul écrivain reste nécessaire. Aucun timer ni autorisation PROD.
